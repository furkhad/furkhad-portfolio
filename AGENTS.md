# Working rules for AI coding agents

## Goal
Maintain a high-quality personal portfolio for Furkhad Ahmed, an early-career computer science engineering student focused on cybersecurity, automation, and systems work.

## Working principles
1. Think before acting: inspect the current structure and state the intended change before editing when scope is ambiguous.
2. Simplest solution first: this is intentionally a dependency-free static site. Do not add frameworks, packages, trackers, animation libraries, or backends without a concrete requirement.
3. Make surgical changes: preserve unrelated content and behavior; avoid rewriting working files wholesale for small requests.
4. Verify results: after each meaningful change, check HTML/CSS/JS, run any available browser checks, test mobile and desktop, and inspect the diff.
5. Be honest: never invent awards, work experience, metrics, security outcomes, or project capabilities. Describe simulations as simulations and prototypes as prototypes.

## Site constraints
- Keep content readable, accessible, keyboard navigable, responsive, and usable when JavaScript is unavailable.
- Honor `prefers-reduced-motion` and use visible focus states.
- Avoid external scripts, trackers, unnecessary network requests, and heavy visual effects.
- Keep navigation and project links functional; do not use fake forms or dead buttons.
- Do not add claims of professional experience, certifications, metrics, or production readiness without evidence from the owner.
- Only present security scanning as authorized testing; never add functionality that encourages unauthorized testing.
- Keep project descriptions synchronized with their actual repositories.
- Ask before publishing personal contact information not already explicitly approved for public display.
- Before finalizing, run appropriate checks and report exactly what passed or failed.
